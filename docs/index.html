Apple Intelligence · Foundation Models · macOS 26+

The free AI already on your Mac.

apple-llm lets Node.js and Python call the language models Apple ships with macOS: the on-device model behind Apple Intelligence, and Apple's large model on Private Cloud Compute. No API key, no account, no model download, no Xcode.

Install

Nothing compiles at install time. A small Swift helper builds on first use (a few seconds, once), and the npm and pip packages share one cached binary.

shell
npm install apple-llm
pip install apple-llm
xcode-select --install   # Xcode Command Line Tools, once (full Xcode not needed)

apple-llm probe          # what this Mac can do
apple-llm setup-cloud    # once, only for the cloud tier
Read this before you use it. You need macOS 26+ on Apple Silicon with Apple Intelligence turned on. It won't run anywhere else (the import still succeeds, and probe() tells you why). The cloud tier sends your prompt to Apple's servers, so it isn't local; tier: 'auto' uses the device whenever it can.

Quickstart

One client covers both tiers (device, cloud, auto). Node is async; Python ships sync and async clients.

TypeScript
import { AppleLLM, probe } from 'apple-llm';
import { z } from 'zod';

await probe(); // { device: { available, contextSize, variant }, cloud: { … } }

const llm = new AppleLLM(); // tier defaults to 'auto'
await llm.text('Summarize this in one line', { system: 'You are terse.' });

// Guaranteed shape on device, typed by Zod
const Contact = z.object({ name: z.string(), email: z.string().email() });
const contact = await llm.json('Reach Grace at grace@navy.mil', { schema: Contact });

// Streaming; breaking out of the loop stops the model
for await (const delta of llm.stream('Write a haiku about bridges')) {
  process.stdout.write(delta);
}

llm.close();
Python
from apple_llm import AppleLLM, probe
from pydantic import BaseModel   # optional: pip install 'apple-llm[pydantic]'

class Person(BaseModel):
    name: str
    born: int

probe()  # {"device": {...}, "cloud": {...}}

with AppleLLM(tier="device") as llm:
    llm.text("Summarize this in one line", system="You are terse.")
    person = llm.json("Ada Lovelace, born 1815.", schema=Person)
    person.born  # 1815, a validated Person rather than a dict

    llm.stream("Count to three.", on_delta=print)

Know what it's for

The on-device model is small (~20B sparse, 1–4B active, 8,192-token context). Used for the right jobs it's fast, private and free. Prompting won't make it good at the wrong ones.

Good at

  • Classification, tagging and topic extraction
  • Pulling fields out of text into guaranteed JSON
  • Reading receipts and screenshots (OCR, macOS 27)
  • Rewriting, proofreading, summarising, short drafts
  • Private processing of personal data, offline

Reach for something else

  • Code generation: use a bigger model
  • Multi-step reasoning: the cloud tier reasons, the device model doesn't
  • Long inputs: cloud handles 32k tokens, device 8k
  • Linux, Windows or Intel Macs: there's no fallback

What you get

A full LLM SDK, plus two more ways in: an OpenAI-compatible server and a Vercel AI SDK provider. Tags show which tier or package each feature needs.

device

Structured output you can trust

Constrained decoding means the model can't produce anything but your schema. Pass Zod, ArkType, Valibot, pydantic or plain JSON Schema. On the cloud tier, JSON is recovered and validated.

devicenpm

Tool calling

The model calls your JavaScript mid-generation, with arguments guaranteed to match the parameter schema. You can mix in Apple's on-device ocr, barcode and spotlight.

device

Real streaming

Stream text deltas and partial JSON objects as they generate. Breaking out of for await stops the model itself, not just the promise.

both tiers

Conversations

OpenAI-style message lists are sent as Apple's native transcript and trimmed from the oldest end when the window fills. Named sessions survive restarts.

npm

OpenAI-compatible server

apple-llm serve exposes /v1/chat/completions with streaming, tools, JSON Schema response_format and images. It binds to localhost only, and the API key is optional.

npm

Vercel AI SDK provider

apple() works with AI SDK 6 and 7: generateText, streamText, generateObject, multi-step tools and images.

both tiers

Images and documents

Attach images and text files by path. A missing file raises an error rather than being dropped silently.

device

Write with Siri presets

rewrite, proofread, summarize, draft and tone run on permissive guardrails, which don't refuse to touch your text.

device

Built for production

Count tokens before you send, get byte-identical output from seeded sampling, and branch on typed errors like ContextLengthError and ModelUnavailableError.

A local OpenAI endpoint

Point any OpenAI client at it (the official SDKs, LangChain, LlamaIndex, Open WebUI, editor plugins) with any API key. It serves the on-device model unless a client asks for apple-private-cloud by name.

shell
npx apple-llm serve
# apple-llm serving an OpenAI-compatible API at http://127.0.0.1:11436/v1
# options: --port 11436  --api-key <key>  --cors <origin>  --tier cloud
TypeScript: openai client
import OpenAI from 'openai';

const openai = new OpenAI({ baseURL: 'http://127.0.0.1:11436/v1', apiKey: 'unused' });
const res = await openai.chat.completions.create({
  model: 'apple-on-device', // or 'apple-private-cloud'
  messages: [{ role: 'user', content: 'Tag this: sourdough with a rye starter' }],
});
Python: openai client
from openai import OpenAI

client = OpenAI(base_url="http://127.0.0.1:11436/v1", api_key="unused")
client.chat.completions.create(
    model="apple-on-device",  # or "apple-private-cloud"
    messages=[{"role": "user", "content": "Tag this: sourdough with a rye starter"}],
)

The server comes with the npm package, so npx works even if your app is written in Python.

Vercel AI SDK

TypeScript
import { generateText } from 'ai';
import { apple } from 'apple-llm/ai-sdk';

const { text } = await generateText({
  model: apple(), // on device; apple('cloud') for Private Cloud Compute

CLI

Both packages install the same apple-llm command; chat and serve come with the npm package. It's also the quickest way to try the model.

shell
apple-llm chat                                          # interactive, streamed
apple-llm run --schema person.json "Ada, 1815"          # guaranteed JSON
apple-llm run --tool ocr --image receipt.png "Read the total."
apple-llm run --session trip "My cat is Biscuit."
apple-llm rewrite "gonna grab a bite"                   # + proofread, summarize, draft
apple-llm ask-screen "Summarize what is on this schedule."
apple-llm count --system "You are terse." -             # tokens before sending

Three traps worth knowing

  1. Never set temperature: 0. Constrained decoding already guarantees the schema, and greedy decoding degenerates: a 2s call became 20s. The default is 0.4. Use a seed if you need reproducible output.
  2. Bound your arrays with maxItems. Apple honours it but ignores maxLength on strings.
  3. Use one client for many calls. A long-lived helper takes ~1.5s per call, against ~17s when spawning a process per call. Apple serialises inference, so concurrency buys nothing.

How it works

The package is about fifteen hard-won constraints written down as working code, so nobody has to find them again.

A small Swift helper

It's compiled with swiftc on first use, cached, and shared by the npm and pip packages. One long-lived process speaks newline-delimited JSON, because a process per call costs ~17s.

Apple's schema dialect

Your JSON Schema is rewritten into the restricted GenerationSchema dialect Apple's decoder accepts. Each of its nine rules was found by a rejected schema, and the test corpus runs against Apple's own decoder.

A shortcut for the cloud

The Private Cloud Compute API needs an entitlement no package can ship, so setup-cloud generates a shortcut and signs it on your machine. Nothing is pre-signed, hosted or downloaded.

FAQ

Is it really free?

Yes. The on-device model has no key and no limits. The cloud tier is free as well, but Apple applies a per-device quota; probe() reports it, and running out raises a typed QuotaError.

Is it local and private?

The on-device tier is: nothing leaves your Mac. The cloud tier sends your prompt to Apple's Private Cloud Compute. tier: 'auto' prefers the device, and by default the server only uses the cloud when a client asks for apple-private-cloud.

What do I need?

macOS 26 or later on Apple Silicon, with Apple Intelligence turned on, plus the Xcode Command Line Tools (xcode-select --install). Intel Macs, Linux and Windows aren't supported. The package still installs there, and probe() says why the model is unavailable.

How is this different from Ollama or LM Studio?

Those tools run open-weights models that you download and choose, and they're the better option for code and long reasoning. apple-llm uses the model macOS already has, so there's nothing to download or manage. You also get schema-guaranteed JSON and free access to Apple's server model. Plenty of people will want both.

Can I use it with my existing OpenAI code?

Yes. Run npx apple-llm serve, set your client's base URL to http://127.0.0.1:11436/v1, and use the model apple-on-device. Streaming, tools, JSON Schema response_format and images are supported.

Does Python have everything Node has?

Not yet. In 0.2, Python covers text, json (with pydantic), streaming, sessions, images, documents, Apple's built-in tools and the Write-with-Siri presets. Your own function tools, Zod schemas, the server and the AI SDK provider are npm-only for now.

Is this made by Apple?

No. apple-llm is an independent, MIT-licensed open-source project. It isn't affiliated with or endorsed by Apple.
