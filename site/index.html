01 What macOS 27 changed

macOS 27 is when the free models got good.

macOS 26 introduced the on-device model. macOS 27 doubled its context window, gave it eyes and tools, and swapped the cloud model for a much bigger one. apple-llm supports all of it.

macOS 26 still works, with a 4,096-token window and without these additions.

  1. cloud

    Siri AI's model, in the cloud tier

    Golden Gate replaced the cloud model with Apple's next-generation server model, the one Siri AI runs on. It reasons, reads images, holds 32,768 tokens and can search the live web.

  2. device

    Twice the context 4,096 → 8,192 tokens

    Enough for a long email thread, a meeting transcript or a few documents in a single prompt.

  3. device

    Images, on device

    Pass a photo, scan or screenshot by path. Nothing leaves the machine.

  4. device

    Apple's own tools

    The model can call Apple's on-device OCR, barcode reader and Spotlight's semantic index, which gives you local RAG over your own files.

  5. device

    Tokens you can count

    Count a prompt before you send it, and get input, output and cached token usage back from every call.

  6. both

    A framework that describes itself

    probe() reports the model variant, what it supports and whether your cloud quota is spent, read straight from the framework rather than from the docs.

02 The cloud model

Apple's big model, from a plain Node or Python script. No other package we found gets there.

On macOS 27, PrivateCloudComputeLanguageModel is public API and reports itself available. Then every call fails with ModelManagerError 1046, unless your binary carries a managed entitlement that Apple grants only to signed apps in the App Store Small Business Program.

apple-llm takes a different route. Shortcuts already holds that entitlement, so apple-llm setup-cloud builds a shortcut and signs it on your Mac. Nothing is pre-signed, hosted or downloaded, and there's no developer account.

04 Code

Five ways in.

A library for each language, a drop-in OpenAI endpoint, a Vercel AI SDK provider and a CLI. One client covers both tiers, and auto prefers the device.

import { AppleLLM, tool } from 'apple-llm';
import { z } from 'zod';

const llm = new AppleLLM(); // 'auto': the device when it can, else the cloud

// Guaranteed shape on device: the decoder cannot produce anything else
const Contact = z.object({ name: z.string(), email: z.string().email() });
const contact = await llm.json('Reach Grace at grace@navy.mil', { schema: Contact });

// Your own functions, called mid-generation
const getWeather = tool({
  name: 'getWeather',
  description: 'Current weather for a city',
  parameters: z.object({ city: z.string() }),
  execute: async ({ city }) => ({ city, tempC: 21, sky: 'sunny' }),
});
await llm.text('Do I need an umbrella in Paris?', { tools: [getWeather] });

// Stream; breaking out of the loop stops the model
for await (const delta of llm.stream('Write a haiku about bridges')) {
  process.stdout.write(delta);
}
from apple_llm import AppleLLM
from pydantic import BaseModel   # optional: pip install 'apple-llm[pydantic]'

class Person(BaseModel):
    name: str
    born: int

with AppleLLM(tier="device") as llm:
    person = llm.json("Ada Lovelace, born 1815.", schema=Person)
    print(person.born)  # 1815, a validated Person rather than a dict

    llm.text("Read the total.", images=["receipt.png"], tools=["ocr"])
    llm.stream("Count to three.", on_delta=print)

with AppleLLM(tier="cloud") as cloud:  # after: apple-llm setup-cloud
    cloud.text("Solve this step by step: ...")
npx apple-llm serve   # OpenAI-compatible API at http://127.0.0.1:11436/v1
# options: --port 11436  --api-key <key>  --cors <origin>  --tier cloud
from openai import OpenAI

client = OpenAI(base_url="http://127.0.0.1:11436/v1", api_key="unused")
client.chat.completions.create(
    model="apple-on-device",  # or "apple-private-cloud"
    messages=[{"role": "user", "content": "Tag this: sourdough with a rye starter"}],
)

Works with the official SDKs, LangChain, LlamaIndex, Open WebUI and editor plugins. It supports streaming, tools, JSON Schema response_format and images, and binds to localhost only.

import { generateText } from 'ai';
import { apple } from 'apple-llm/ai-sdk';

const { text } = await generateText({
  model: apple(), // on device; apple('cloud') for Private Cloud Compute
  prompt: 'Write a one-line release note for a bug fix.',
});

AI SDK 6 and 7: generateText, streamText, generateObject, multi-step tools, images and abort signals.

apple-llm chat                                     # interactive, streamed
apple-llm run --schema person.json "Ada, 1815"     # guaranteed JSON
apple-llm run --tool ocr --image receipt.png "Read the total."
apple-llm run --session trip "My cat is Biscuit."
apple-llm rewrite "gonna grab a bite"              # also proofread, summarize, draft
apple-llm ask-screen "Summarize what is on this schedule."
apple-llm count --system "You are terse." -        # tokens before sending

The pip and npm packages install the same apple-llm command; chat and serve come with npm.

05 Fit

Small model, right jobs.

The on-device model is roughly 20B sparse with 1–4B active. Used for what it's good at, it's fast, private and free. No amount of prompting makes it good at the rest.

Reach for it

  • Classifying, tagging and extracting topics
  • Pulling fields out of text into guaranteed JSON
  • Reading receipts and screenshots
  • Rewriting, proofreading and summarising
  • Private data that shouldn't leave the Mac

Reach past it

  • Writing code: use a bigger model
  • Long reasoning: use the cloud tier
  • Inputs over 8k tokens: use the cloud tier
  • Linux, Windows or Intel Macs: not supported

06 Field notes

Fifteen constraints, found the expensive way.

The package is mostly these, written down as working code so nobody has to find them again. Six of them:

  1. Never set temperature: 0

    Greedy decoding under a schema degenerates. One run padded an array forever, then wrote 2.7KB of "tasks-tasks-tasks-…" inside a single string.

    2s → 20s per call. Default is 0.4.

  2. One process, not one per call

    Spawning a helper per request makes every call pay for loading the model again. One long-lived helper keeps it resident.

    ~17s → ~1.5s per call

  3. Concurrency buys nothing

    Apple serialises inference. Four concurrent requests took as long as four sequential ones, so the queue serialises on purpose.

    29.19s parallel vs 29.45s sequential

  4. Every pattern is rejected

    Even ^[A-Z]{3}$ fails with UnsupportedGuide, and Zod adds one to .email(). Patterns are stripped for the decoder and checked on the reply instead.

    1 of 9 schema-dialect rules

  5. A schema mistake is invisible

    Collapsing a number-or-string union to string made it impossible for the model to emit a status code. It wrote ": 201" instead, with no error anywhere.

    Wrong answer, no warning

  6. WFLLMPrompt, not WFInput

    With the wrong key, the shortcut imports fine, silently discards the prompt, then blocks forever on an interactive panel.

    The most expensive bug available

07 Questions

Is it really free?
Yes. The on-device model has no key and no limits. The cloud tier is free too, within a per-device quota from Apple; probe() reports whether you're under it, and running out raises a QuotaError.
Is it private?
The device tier is: nothing leaves your Mac. The cloud tier sends your prompt to Apple's Private Cloud Compute. auto uses the device whenever it can.
What do I need?
macOS 26 or 27 on Apple Silicon, with Apple Intelligence on, plus the Xcode Command Line Tools (xcode-select --install). Full Xcode isn't needed. On anything else it installs but reports why it can't run.
Does Python have everything Node has?
Not yet. Python has text, JSON with pydantic, streaming, sessions, images, Apple's built-in tools and the writing presets. Your own function tools, Zod, the server and the AI SDK provider are npm-only for now.
